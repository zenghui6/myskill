## 09:36 · 修改 Skill · trace-log-analyzer

**原因：** 用户反馈查日志的诉求并不总是定位 Bug，很多时候只是想理清一条 trace 的调用流程；但技能默认把「查日志」导向「根因分析 + 修复建议」，agent 一直刨根问底，把流程拉得很长。希望 agent 能先对齐意图（理清流程 vs 定位 Bug），协同推进，遇到分叉先反问用户而不是自动深挖。

**改动：**
- 重写 `~/.omp/skills/trace-log-analyzer/SKILL.md`，新增「核心原则」：意图先行 / 协同优先及时反问 / 流程模式默认收敛。
- 工作流新增第 0 步「确认意图（必做）」：明确目标走对应模式；只说查日志/看流程默认进「理清流程」；提到报错/根因才进「定位 Bug」；看不出意图则反问。
- 新增「理清流程」输出模式：按时间/调用顺序列链路节点，标出异常点，只陈述事实、不做根因推测、不给修复建议，结尾问是否继续定位根因。
- 「定位 Bug」模式保留原固定结论格式（现象/时间线/根因分析/代码证据/修复建议），仅在用户明确要排查时启用。
- 新增第 5 步「协同反问」：追上下游日志、统计同类错误、写 bug 文档等深挖动作必须先征询，不自动做。
- description 同步补充「理清链路/流程」触发场景。

**影响：**
- 查日志默认交付从「bug 结论」变为「流程链路」+ 收尾反问，流程显著缩短。
- bug-doc-required 不再被 trace 排查隐式触发，是否产出 bug 文档由用户显式决定。
