## 10:44 · 修改 Skill · git-commit-standards 移除 Author 获取与署名要求

**原因：** 用户指出提交信息里的 `Author: 姓名 <邮箱>` 没有必要——git 提交自带账户信息，账户即可直接溯源。原规则要求 AI 先读 `git config user.name / user.email`、校验非空、再由脚本拼接 Author 行，属冗余步骤，整条删除。

**改动：**
- `git-commit-standards/scripts/build-commit-message.js`：删除 `readGitValue()`、`buildMessage` 的 name/email 参数与 Author 拼接、`writeMessageFile` 的 git 用户读取及缺失校验
- `git-commit-standards/SKILL.md`：删除提交格式块与格式规则表中的 Author 条目；删除「第一步：获取提交者信息」整节；五步清单收敛为四步并同步后续编号与交叉引用；删除 3 处示例及多文件示例中的 Author 行；删除末尾「团队配置」章节；frontmatter description 去掉 `real Author format`；Red Flags 移除「跳过读取 git config」条目
- 保留 AI 署名禁令（禁止追加 `Co-Authored-By` / `Generated by` / 机器人 emoji）及 hook 兜底描述（校验标题 + 三段正文）

**影响：**
- 提交信息统一为 `标题 + 【改动】【原因】【结果】`，不再生成 Author 行；提交者身份由 git 账户（`git log`）承担
- 执行流程由五步变四步；不再因 git 用户未配置而中断提交
- 插件包内 `hooks/check-commit-no-ai-signature.js` 的 Author 校验逻辑不在本仓库（本仓库只含 skills 目录），如继续在启用该 hook 的宿主提交，仍会被要求 Author 行，需要时另行同步

## 16:42 · 修改 Skill · git-commit-standards 提交信息剔除测试细节与验证结论

**原因：** 实战中发现两类噪音：(1)【结果】里写“修复后通过，XxxTest 全量 5 用例绿（fast-test 增量执行 + jdtls diagnostics clean）”这类验证结论——测试通过本就是提交前提，与提交信息无关；(2)【改动】里展开新增测试的基建与细节（测试类、用例方法名、PowerMock 静态 mock、ArgumentCaptor 断言字段），把业务改动的重点挤到后面。用户要求：结果不写测试通过；新增测试只一句话说明覆盖情况。

**改动：**
- `git-commit-standards/SKILL.md`：
  - body 三段重点：【结果】新增“不写测试通过、用例全绿、编译或诊断 clean 等验证结论”；新增“测试改动从简”条目（一句话说明覆盖了什么，禁止列测试类清单、用例方法名、mock 与断言细节）；尾句去掉“测试结果可以作为补充”
  - Red Flags 新增两行：把验证结论写进【结果】、把测试细节展开进【改动】
  - 多文件示例新增一行测试覆盖示例（InventoryReserveServiceTest 覆盖预占、释放主路径与并发超卖场景）

**影响：**
- 含测试改动的提交信息不再出现测试基建与验证过程的描述，正文重心回到业务改动本身
- 测试覆盖仍保留一句话交代，读者可了解验证范围
