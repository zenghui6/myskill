# 开发日志 · 2026-11-13

## 新增 Skill · git-merge-conflict-via-mr

**原因：** 团队分支策略与通用「冲突解决」技能不一致：`develop` / `master` 由 GitLab 保护，本地一律不允许推送；合入前必须从源分支新建 `merge` 分支，把目标分支合进来解决冲突，再推 `merge` 分支并发 MR。通用技能（`mattpocock/skills@resolving-merge-conflicts`、`warpdotdev/common-skills@resolve-merge-conflicts`）只覆盖冲突 hunk 的解决，不覆盖分支护栏，靠人记容易违规推送受保护分支。

**改动：**
- 新增 `git-merge-conflict-via-mr/SKILL.md`：六条硬门禁（禁推受保护分支、必须新建 merge 分支、合并方向固定、禁 abort/reset --hard/--force、未过检查不提交、仅显式调用不自动触发）、分支命名规则 `merge.<用户名>.<源分支末段>2<目标分支>`、八步命令序列、冲突解决细则（对齐 mattpocock 技能：追原始意图、保留双方语义、不发明新行为、大文件抽 hunk）、校验与失败模式表
- `docs/skill-flow.md`：横切技能表新增本技能行并标注「仅显式调用，不自动触发」，技能总数 23 → 24

**影响：**
- 合入 `develop` / `master` 的冲突处理有了可执行护栏，agent 不会再把本地源分支直接推向受保护分支
- 该技能不进任何自动路由链，只有用户显式调用 `/git-merge-conflict-via-mr` 才生效
- 与 `git-commit-standards`（提交信息）、`test-release-doc`（提测）、`review-platform`（MR 评审跟进）串联，但相互独立触发

## 补充 · 大文件冲突按索引阶段取版本

**原因：** 冲突集中在 `OrderDecorator` 这类数千行文件时，整文件读入既费上下文又容易顺手重写；外部 `warpdotdev/common-skills@resolve-merge-conflicts` 用 Python 脚本抽取 hunk，但为一条命令引入额外技能与自动触发成本不划算。

**改动：** `git-merge-conflict-via-mr/SKILL.md` 冲突解决细则新增「大文件冲突：按索引阶段取版本」小节：`git diff --name-only --diff-filter=U` 列未解决文件、`git diff --cc <file>` 看组合 diff、`grep -n` 定位冲突块行号、`git show :1:/:2:/:3:<file>` 取祖先与双方版本、`git diff --no-index` 只比两侧差异；并约定 `:1:`~`:3:` blob 在 `git add` 后消失、逐文件 `git add`、收尾用 `grep` 与 `git diff --cached --check` 复查。

**影响：** 不装外部技能也能在超大文件冲突时只读必要区间，减少误改与上下文浪费。

## 补充 · 本地 pre-push 护栏

**原因：** 技能只能约束 agent 自身行为，人和其它工具仍可直接 `git push origin develop`。需要一层与技能互补的本机护栏，但必须说明它可被 `--no-verify` 绕过。

**改动：**

- 新增本机全局 hook `~/.githooks/pre-push`：解析 stdin 的 refspec，目标为 `refs/heads/develop` 或 `refs/heads/master` 时 `exit 1` 并提示改走 merge 分支 + MR；受保护列表可用 `PROTECTED_BRANCHES` 覆盖；默认不拦 `main`；末尾链式调用 `<git-dir>/hooks/pre-push.local` 以免全局 `core.hooksPath` 吞掉项目自有 hook
- `git config --global core.hooksPath "C:/Users/zenghui/.githooks"` 启用（安装前已确认本机 `F:/sesun` 各仓库无自定义 hook）
- `git-merge-conflict-via-mr/SKILL.md` 新增「本地护栏（可选安装）」节，写清安装 / 卸载 / 链式机制 / 绕过限制

**验证（隔离裸仓库实跑）：** 普通分支推送成功；`git push origin HEAD:develop`、`HEAD:master` 均被 hook 拒绝（exit 1，远端未创建分支）；`pre-push.local` 链式调用生效；`git push --no-verify origin HEAD:develop` 可绕过并成功建分支 —— 证明本地 hook 只防误操作，真正护栏仍是 GitLab Protected Branches。

**影响：** 误推受保护分支在推送前即被拦下；同时明确告知 `--no-verify` 绕过路径与 GitLab 侧保护的必要性。
