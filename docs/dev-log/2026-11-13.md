# 开发日志 · 2026-11-13

## 新增 Skill · git-merge-conflict-via-mr

**原因：** 团队分支策略与通用「冲突解决」技能不一致：`develop` / `master` 由 GitLab 保护，本地一律不允许推送；合入前必须从源分支新建 `merge` 分支，把目标分支合进来解决冲突，再推 `merge` 分支并发 MR。通用技能（`mattpocock/skills@resolving-merge-conflicts`、`warpdotdev/common-skills@resolve-merge-conflicts`）只覆盖冲突 hunk 的解决，不覆盖分支护栏，靠人记容易违规推送受保护分支。

**改动：**
- 新增 `git-merge-conflict-via-mr/SKILL.md`：六条硬门禁（禁推受保护分支、必须新建 merge 分支、合并方向固定、禁 abort/reset --hard/--force、未过检查不提交、仅显式调用不自动触发）、分支命名规则 `merge.<用户名>.<源分支末段>2<目标分支>`、八步命令序列、冲突解决细则（对齐 mattpocock 技能：追原始意图、保留双方语义、不发明新行为、大文件抽 hunk）、校验与失败模式表
- `docs/skill-flow.md`：横切技能表新增本技能行并标注「仅显式调用，不自动触发」，技能总数 23 → 24

**影响：**
- 合入 `develop` / `master` 的冲突处理有了可执行护栏，agent 不会再把本地源分支直接推向受保护分支
- 该技能不进任何自动路由链，只有用户显式调用 `/git-merge-conflict-via-mr` 才生效
- 与 `git-commit-standards`（提交信息）、`test-release-doc`（提测）、`review-platform`（MR 评审跟进）串联，但相互独立触发
